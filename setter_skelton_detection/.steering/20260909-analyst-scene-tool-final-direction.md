# 2026-09-09: アナリスト向け骨格抽出ツールへの方針転換（最終方向性）

同日の`.steering/20260909-position-label-pilot.md`（7クラスのポジション別ラベル検出パイロット）を検討した後、さらに議論を重ねて方針を転換した。こちらが本日時点の最終方向性で、`plan.md`に反映済み。

## 経緯（このファイルに至るまでの検討の流れ）

1. `position-label-pilot`（7クラス分類）を採用しようとしたが、「Trackingというタスクがあると聞いた」という話から、単一フレームでのポジション分類よりトラッキング（`model.track()`）でラリー全体の行動パターンから推定する方が理論的に有望では、という再検討が始まった
2. サーブレシーブの瞬間に限定すればローテーションのルール上ポジションが一意に決まる、という案も出たが、既存100枚（トスの瞬間）が使えなくなり新規データ収集が必要になるというトレードオフがあった
3. 「アナリストが背番号を入力→その選手をトラッキング」案が出たが、背番号OCRの実装コストが高いことを指摘し、「クリックで選手を選ぶ」方式を代替案として提示
4. 最終的に「動画をアップロード→好きなシーンを選ぶ→そのフレームの全選手のbbox・骨格を表示→アナリストが好きな選手を選んでダウンロード」という、**トラッキングもポジション分類も不要な、最もシンプルな設計**に収束した
5. ただし「セッターのトス」「スパイカーのジャンプ」等、重要な瞬間の骨格精度を落としたくないという要望から、素のモデルではなく**引き続きファインチューニングする**方針に修正された

## 決定事項

- **モデル**: ファインチューニングを継続する（素のモデルでは重要な瞬間の姿勢検出精度が不十分なため）
- **学習データの方針転換**: `plan.md`の旧方針（紛らわしいポーズの他選手は「ハードネガティブとして未アノテーションのまま」）から転換し、**セッター以外の選手（スパイカー・ブロッカー等）の複雑な姿勢も、通常のbbox+keypointsとして正しくアノテーションする**（複数人・単一`person`クラス）
- **ポジション分類は不要**: AIによるポジション判定（7クラス分類・トラッキング・背番号OCR）はすべて不要。アナリストが選手を選ぶ時点で誰かを把握しているため
- **ツール設計**: 動画アップロード→シーン（フレーム）選択→そのフレームのみ推論→検出された選手を番号付き表示→アナリストが選択→keypoints/bboxをダウンロード
- **デプロイ**: まずHugging Face Spaces（ZeroGPU）で実装。quota等の問題があれば別ホスティングを検討
